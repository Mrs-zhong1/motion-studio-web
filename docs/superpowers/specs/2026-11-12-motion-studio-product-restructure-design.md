# Motion Studio 产品级重构设计

## 目标

把 Motion Studio 从“打开即进入长面板编辑器”的工程验证页，重构为面向非技术创作者的完整产品：先发现模板，再沉浸预览，最后进入始终可见画布的可视化编辑器。现有 20 个动效组件、离线 Three.js/GLB/PBR、镜头、图层、时间轴、工程 JSON 和单文件 HTML 导出必须保持可用。

## 用户体验

### 模板发现

- 默认首页是模板库，不再直接进入编辑器。
- 左侧为产品导航，顶部为模板分类，主区域为 8 张大型、非对称模板卡片。
- 8 套完整模板分别是 Editorial Portfolio、3D Product Experience、Cinematic Journey、Architecture Studio、Creative Agency、Fashion Lookbook、Interactive Gallery、Modern SaaS。
- 每套模板必须由不同的章节组合、版式节奏、相机/图层配置和交互骨架构成，不允许只换颜色。
- 点击模板进入全屏沉浸预览。预览使用与导出相同的 renderer 生成真实可滚动、悬停和 3D 内容。
- 预览工具条包含关闭、桌面/手机切换、重播、使用此模板。

### 可视化编辑器

- 顶部工具条承载返回模板库、工程名、简单/专业模式、保存、导入和导出。
- 主工作区固定为三栏：左侧章节和三级资产，中央实时画布，右侧上下文属性。三栏独立滚动，中央画布不随侧栏长度消失。
- 左侧章节以缩略列表呈现，可点击定位和拖拽排序；资产分为 L1 完整模板、L2 章节模板、L3 基础动效。
- 中央画布支持直接选择、缩放、桌面/手机、交互预览、全屏以及收起两侧栏。
- 右侧只显示当前章节/图层相关属性。简单模式隐藏镜头、关键帧和多图层高级控制；专业模式全部显示。
- 底部时间轴可展开/收起，并与章节、图层和滚动进度同步。

## 技术方案

继续使用现有单文件原生 HTML/CSS/JS 架构，不引入新框架。`stage9/Motion-Studio-Unified-Editor.html` 仍是编辑器源文件，`stage9/build-offline.mjs` 继续把固定版本 Three.js 注入离线发布文件。新增发现页和编辑器外壳，但保留现有 registry、project schema、section renderer、GLB 验证、图层和导出实现。

模板预览通过把模板定义标准化为工程对象，再调用同一个 `exportDocument()` 核心生成 iframe `srcdoc`。选择模板、保存、再次打开与导出都使用同一工程数据，不维护第二套静态截图或伪预览。

## 约束与非目标

- 不复制 GSAP Showcase、MotionSites 或其他站点的专有源码和素材，只借鉴发现与作品展示的信息架构。
- 不移除或重写与本次产品壳无关的 3D/GLB 解析能力。
- 不宣称原生 Safari、真实 Apple GPU 或移动设备性能已通过；自动化 WebKit 只代表桌面引擎冒烟。
- 本轮不加入云账号、协作、后端存储或付费能力。

## 视觉系统

- 发现页：变化度 9、动效 7、密度 3；编辑器：变化度 5、动效 4、密度 6。
- 全站采用墨黑/暖白基底和单一酸性黄绿强调色，使用本地系统字体栈，避免外部字体请求破坏离线导出。
- 模板卡片使用每套独立的构图语言，而不是统一卡片换皮。
- 动画只用于层级进入、预览状态切换、卡片反馈和画布操作反馈，并提供 reduced-motion 降级。

## 验收标准

- 首页展示 8 套可选择模板，每套能进入真实 preview renderer。
- 8 套模板均能进入编辑器、保存 JSON、重新打开并导出离线 HTML。
- 编辑器三栏独立滚动，中央画布可缩放、全屏、切换设备、收起侧栏。
- 简单/专业模式和可折叠时间轴可用。
- `registry.length === 20`，既有 GLB、图层、相机和导出测试不回归。
- Chromium、Firefox、WebKit 产品旅程通过；发布工作流通过后再更新 GitHub Pages。

## 已考虑的方案

1. 在旧编辑器上只改样式：风险低，但无法解决入口、预览和信息架构问题，否决。
2. 新建 React/Vite 应用并迁移 renderer：长期可扩展，但会显著增加本轮迁移风险，并威胁离线单文件链路，否决。
3. 在现有单文件 renderer 外增加产品壳并标准化模板工程对象：能保留已验收能力，又能完成完整体验重构，采用。
